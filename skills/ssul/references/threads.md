# Multi-post threads, first comment, and posting

## When a thread, when a single post

A thread only when each post can stand alone and the idea truly needs more than 500 characters: a numbered teaching list, a story with a build, a process the user ran. A one-line idea padded into a thread reads as padding. If it fits in one post, keep it one post.

## Building a thread

1. **Post 1** carries the promise and an open loop, and must work alone in the feed. No "스레드 🧵" label as the hook. Disclosure, if needed, goes here.
2. **Front-load**: the strongest point goes in post 2, not at the end.
3. **One idea per post**, 4 to 7 posts for teaching or list threads, each under 500 characters.
4. **Each post stands alone**: someone who sees only post 4 still understands it.
5. **Last post**: the most quotable line, plus at most one easy question.
6. Mark breaks with `---` on its own line so the user sees exactly how it splits. Show the character count per post.

## First comment

- Links go in the first reply under the post, not in the post (links in the first post tend to cut reach, and they pull readers away before they react).
- The first comment can also add a source, a correction, or the "more details" that would bloat the post.
- Do not use the first comment to hide a sponsorship disclosure; that must be in the post (`disclosure.md`).

## Posting

- No verified study gives a best posting time for Korea. Suggest the user post when their own audience is online and compare a few times, rather than citing a rule.
- Replies in the first hour matter; suggest the user stay to answer early replies.
- Never publish or schedule. ssul returns text only.
